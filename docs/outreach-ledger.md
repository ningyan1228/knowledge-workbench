# 共享开发信发送记录

此功能只记录**人工确认已实际发送的首封开发信**；复制草稿、下载草稿或打开邮件窗口都不会自动标记。不会发送邮件，也不会写入 CRM。

## 现有 Supabase 项目启用

在现有 `knowledge-workbench` Supabase 项目的 SQL Editor 中，完整执行 `supabase/migrations/202609290001_shared_outreach_sent_ledger.sql`。不要新建或重置项目。该迁移只新增 `market_intel_outreach_sends` 表、索引、RLS 策略和纠错函数；不更新或删除现有客户、联系人、Lead、用户或它们的 RLS。

迁移完成后，你与两位同事分别用现有 Supabase 账号在网站“资料与设置”登录。所有**已登录该项目的账号**共用同一份台账；未登录访客看不到发送数据，也不能标记。如该项目以后加入其他登录账号，他们也会获得相同访问权。

## 日常使用

1. 在地图右侧或线索库看“已发送 / 未记录发送”状态；点状态打开 Company Detail。
2. 发信前复制开发信或点公开邮箱时，系统会实时核对该公司是否已有发送记录；有记录会警告。批量下载也会重新读取台账并排除已记录发送的公司。
3. 邮件**实际发出后**，在 Company Detail 填写实际收件邮箱和发送日期，点“确认已发送”。不同产品下的同一家公司共用一条当前发送状态。
4. 误标记时填写原因来更正；旧记录留存供追溯。不要用“更正”来掩盖真实发送。

此台账是人工记录，不与邮件服务同步。若有人在网站以外发信而未登记，系统无法知道；`未记录发送` 不等于确定未发送。多位同事同时操作时，数据库唯一索引防止同一公司出现两条当前有效发送记录。
