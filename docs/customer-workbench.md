# 客户开发工作台

市场情报的全球地图与线索库共用业务筛选；切换地图／列表保留筛选，默认最近收录优先。

## 开发优先级

评分用于安排开发顺序，不代表采购概率、确认需求或已使用我方产品。应用关联占 35 分（TDS 应用 35，公开市场扩展 25），公司业务证据完整度占 25 分，公开联系入口占 25 分（业务邮箱 25，官网联系页 18，电话 12），需求侧角色占 10 分，同行排除记录占 5 分。80 分起优先开发，60 分起常规开发，其余先补证据。详情显示逐项分值和依据。

## 私人进度与名单

沿用现有 `bookmarks_notes` 表、`owner_id` 与 RLS，无须执行新迁移。私人记录不写进正式客户数据、共享发送记录或 CRM，也不在浏览器本地保存。

- 公司记录使用 `object_type=market_lead_workspace_v1`；公司规范化名称和国家生成固定 UUID；同公司跨产品共用记录。
- `bookmarked` 保存收藏，`note` 的 JSON 保存阶段、跟进日期、私人备注、名单 ID 和公司键。
- 名单使用 `object_type=market_lead_list_v1` 与随机 UUID；`note` 保存名称。删除名单保留客户本身、收藏、备注和进度；其旧成员引用不再展示。
- 写入前核对登录账户并重新读取该公司记录，合并本次修改。不同公司记录分别写入；同一公司被多个设备同时修改相同字段时，以最后保存为准。
- 私人阶段为待开发、待回复、已回复、样品沟通、暂缓。未指定阶段时，有共享实际发送记录显示“已发送开发信”；否则待开发。已实际发送的公司不会被私人“待开发”覆盖。已回复、样品沟通等后续进度继续保留“已发送开发信”里程碑。未知记录显示进度未确认。
- 开发进度的“已发送开发信”筛选读取有效的共享实际发送记录，包含已回复、样品沟通及暂缓的公司，按公司跨产品匹配；误标发送记录撤销后不再计入。“待回复”也包含已发送但尚未记录后续进度的公司。“已发送开发信”不作为可手填的私人阶段，避免仅修改阶段就误记为实际发信。
- 阶段调整不标记实际发信，实际发送仍在原共享发送记录中手动确认。
- 退出或切换账户立即清除私人视图，丢弃前一账户的晚到查询结果。

## 今日开发清单与筛选

优先开发须达到 80 分、处于待开发、且无共享发送记录；最近新增是上述未开发、未发送客户按首次收录倒序排列。今日跟进包含今天及逾期的私人计划，暂缓计划除外。日期使用北京时间。未知发送历史不会被当作未发送；未登录时仍可浏览、筛选公开客户和证据。

产品、大洲、国家、行业／客户类型、应用、联系入口、私人阶段、收藏／名单、关键词可组合筛选。今日清单统计当前业务范围，不包含下方独立的收录日期筛选。时间线和地图／列表展示相同的最终结果。

证据摘要展示公开产品应用、业务依据、需求侧理由、排除结论、核验日期、联系入口与公司名关联说明。去重说明仅适用于同国家、同规范化名称；集团内不同公司不据此自动合并。

## 客户卡片的三个问题

地图卡片直接展示「联系理由」「评估材料」「联系渠道」，列表展示同样内容。联系理由采用已核验公司事实的简短中文结论，不截断句子；完整核验原文、来源链接和核验日期仍在「完整依据」中展开。

`src/lib/leadBusinessFacts.ts` 的中文结论关联原始证据指纹。原文变更或新公司尚无中文结论时，回退到该公司现有原文摘要，避免套用其他公司事实或过期结论。更新中文结论须重新核对该公司的原始证据；不按客户类型自动补造工厂、实验室或产品。

材料名称与功能评估主题来自 `src/lib/functionalProductPitch.ts`，按产品及已核验应用选择，保留「适配待评估 · 采购未确认」。独立研究扩展方向另外显示「扩展应用」；不能将客户成品的防腐性能转为我方材料承诺，或把我方聚氨酯路线说成客户现有体系。

联系渠道使用现有邮箱归属核验及公开入口规则。仅展示实际保存的公开邮箱、官网联系页、LinkedIn、WhatsApp 或电话；缺邮箱标注「邮箱待补」。官网联系页不自动称为表单，电话不自动生成 WhatsApp 链接。打开链接由用户自行操作，不自动发送、提交表单或写入联系记录。

## 开发信主操作与独立筛选

地图卡片和列表以「准备开发信」为主要操作，直接进入开发信页。每次进入均重新核对该公司的共享发送记录，核对完成前不展示草稿；读取失败或未登录显示核对提示与重试入口。复制主题、正文、整封仍使用原有的再次核对流程。缺邮箱不阻止通过公开表单或私信准备正文；不自动发送或登记联系。

有有效发送记录时，主操作变为「查看原参考稿」，旁边提供「发送记录」。原参考稿不等于实际发送原文；现有台账没有保存已发正文。另保留联系渠道和客户详情入口；已发送公司的联系渠道可在卡片渠道标签或详情中查看。

筛选区独立展示发送记录、可用联系渠道、资料完整度；开发准备另列为工作快捷筛选。发送记录的「未查到发送记录」仅表示共享台账无有效记录，包含缺邮箱客户，不证明确定没有发送。「记录待确认」包含未连接及读取失败，失败另有明确提示。邮箱待补、应用证据待补和核验资料待补不依赖发送记录，可与已发送、公开渠道组合筛选。每个维度的数量保留其余维度的当前条件，按公司去重；同一公司可有多个渠道或多个资料缺项。

主页面仅常驻「全部／已记录发送／未查到发送记录」快捷按钮与「渠道与资料筛选」入口。详细维度、统计及说明收进原生模态弹窗；选择立即生效，关闭、Esc 或查看结果后返回列表，已选渠道及资料条件以可移除标签显示。弹窗可重置这些筛选，保留产品、地区、关键词等其他条件。原生弹窗管理键盘焦点，关闭后返回入口，手机可滚动查看全部选项。
# 连续处理客户的工作区（2026-10-21）

- 卡片“联系理由”只显示简短业务事实：公司制造什么、具体产品及用途，不放来源读取过程、核验笔记、联系资料或材料适配推断。对近期缺失摘要的客户按其既有公开证据逐家补齐，保留如“室内”“地板除外”等实际用途限制。摘要仍绑定原始业务证据指纹；证据变更后失效，不复用旧结论。无法安全呈现的长原文或核验笔记显示“业务事实待整理，请查看完整依据”，不机械删掉否定语或截断技术断言。
- 核验原文、来源、日期及“适配待评估 · 采购未确认”均保留在卡片“完整依据”中，展开可读。列表、地图、公司概览和刷新后的数据使用同一显示规则；构建快照同时导出该简短事实，刷新数据不会重新带入核验笔记。发送记录与开发信正文不因卡片文案整理而改变。

- “今日新增／近 7 天新增”旁及主页面结果栏提供“刷新数据”。读取当前网站最新发布的正式公开客户、首次收录时间及配套事实，随后一起更新统计、列表、地图和开发信资料，不重载网页，不重置筛选、排序或已保存的联系记录。加载中禁止重复请求；失败／超时保留旧数据并提示重试，成功显示北京时间更新时间。当前客户已从新版公开库移除且有未保存备注时先确认，取消则不应用新版。
- 每次正式网站构建自动从既有公开前端数据导出带内容哈希的客户快照和小型版本清单；Pages 工作流先追溯首次收录时间，再构建，所以刷新使用同一部署的客户与历史。快照只来自公开数据模块，不包含研究队列、私人联系记录或凭据。读取时校验版本、哈希及数据结构，完整校验后才替换，避免部分更新。未发布或仍在部署中的研究不会显示为新客户。

- 开发信底部复制操作旁常驻“确认已发送”，点击直接弹出当前公司的实际收件邮箱和发送日期，默认采用已核验收件邮箱与今天，支持修改。确认“已实际发送”后保存到原共享台账，继续使用保存前按公司查重与并发去重。取消或复制都不会记录发送；无邮箱客户须填写实际邮箱。已发送时显示“已发送 · 查看记录”，原记录展开、更正入口继续保留。小屏幕确认按钮放在复制按钮下一行，无需查找折叠记录。

- 复制邮箱、主题、正文和整封开发信前，均重新读取该公司的共享邮件发送记录和当前账号私人渠道联系记录。已有发送或表单／LinkedIn／WhatsApp／电话等联系记录时，统一提示日期、渠道与实际入口；两类记录同时存在时一并展示，用户确认后才复制，取消则不写入剪贴板。公司、部门与具名业务邮箱的详情复制按钮也使用同样规则。读取失败或超时阻止复制；私人记录未连接须明确确认，不能当作未联系。已撤销的记录不触发已联系提醒。

- 客户页面以标题、搜索、筛选和列表／地图切换组成一条主操作栏；发送记录的常用快捷筛选仍在主页面。产品、地区、日期、渠道、资料完整度、私人进度与名单统一进入筛选弹窗，已选条件可单独移除。
- 首次使用默认列表，保留用户后续选择的展示方式。桌面宽度超过 1100px 时，左侧客户列表和右侧工作详情独立滚动；切换客户或使用上一家／下一家不重置列表位置。当前详情不属于筛选结果时明确提示。未保存私人备注时，切换客户或展示方式仍须确认。
- 小屏幕改为客户列表与详情浮层，支持关闭、Escape、焦点约束与焦点恢复；桌面内嵌详情采用 region 语义，不锁定页面或拦截列表键盘操作。
- 名片优先显示公司业务事实、可评估材料与公开联系渠道，只有一个主操作；核验日期及原始证据收进完整依据。普通无发送记录使用灰色，已发送为绿色，读取失败单独提示。
- 开发信优先展示主题和正文，复制正文为主操作，复制整封及主题保留。复制操作栏固定在工作详情滚动区域底部；收件邮箱直接可见，其归属证据、产品边界、原 Prompt 和其他联系记录可展开查看。
- 进入开发信前重新核对共享发送记录；复制前再次核对共享发送与私人渠道记录，未连接／失败不视为未发送。已发送公司保留原参考稿，无邮箱公司仍可准备正文；所有联系与发送记录继续由用户在实际投递后手动记录。

# 开发结果

- 导航新增“开发结果”：按公司去重显示实际联系、收到回复、技术沟通、开始样品评估；按产品客户方向、国家／地区及首次已记录联系月份比较，可组合筛选并展开公司清单核对。
- 联系数来自有效共享邮件发送台账和当前账号渠道联系／实际联系补录。后三项须手动记录实际日期和简短依据，各自独立，不从旧进度、复制、下载或其他阶段推算。记录可撤销，撤销不改写邮件台账。0 仅表示未查到记录。
- 新结果接入复制前的实时核对：已记录沟通结果时再次复制邮箱／主题／正文／整封会提醒；同时排除首封准备与批量首封下载。撤销误记后恢复正常判断。
- 新结果存入现有私人客户记录 JSON，沿用账号隔离及跨设备存储，不新增数据库表。共享邮件与私人数据任一未连接／读取失败时显示不可用，不显示为零。用户可刷新记录；无自动邮件、表单、私信或真实客户记录测试写入。
- 批次为首次已记录联系的自然月，结果按该公司当前累计记录计算，不限定发生在该月；缺联系日期的结果单列日期待补。近期批次观察时间短。产品组为公司的公开产品方向，跨产品公司可能重复入组，不作产品结果归因、组间求和或成交概率估计。历史进度须补结果日期及依据后才计入。
